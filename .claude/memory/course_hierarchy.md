## القاعدة (قرار المستخدم — 2026-09-01)
**أي كورس متفرّع منه كورسات تانية (أي كورس آخر `parent_course_id` بيشاور عليه) هو مجرد حاوية بلا محتوى فعلي — يُستبعد تلقائيًا.**

الاستبعاد **بالبنية لا بالاسم**: أي كورس أب جديد يُضاف مستقبلًا يتخفي لوحده بلا أي تعديل كود.

  - **دورة تأسيس 2027** (`40176e62-f9e8-4a85-82ce-5cfb8e65c15c`) — 249

فالعدد الصحيح للكورسات = **2**، لا 3.

النمط المستخدم في الاثنين:
```ts
const list = data || []
const parentIds = new Set(list.map(c => c.parent_course_id).filter(Boolean) as string[])
const visible = list.filter(c => !parentIds.has(c.id))
```

## ما لم يُطبَّق عليه عمدًا (قرار المستخدم)
قوائم اختيار الكورس في **الإشعارات** (`AdminNotifications.tsx`) و**أكواد الخصم** (`AdminCoupons.tsx`) وأي شاشة أخرى — تُركت كما هي، لأن الإشعار أو كود الخصم قد يُقصد به الباقة الرئيسية كلها. أي توسعة للقاعدة خارج الاختبارات ولوحة التحكم تحتاج موافقة المستخدم أولًا.

## ملاحظة مهمة عند التطبيق مستقبلًا
`has_active_course_access` بتعامل الكورس الأب معاملة خاصة: كورس سعره 0 **وله كورسات فرعية** لا يمنح وصولًا مجانيًا. الاشتراك في الأب يمنح الوصول للأبناء (`e.course_id = c.parent_course_id`). لا تلمس هذا المنطق عند أي تعديل على العدّ أو القوائم — العرض شيء والصلاحيات شيء آخر.
