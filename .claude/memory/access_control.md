## أين يُطبَّق القفل فعليًا
القفل ليس في الواجهة فقط — هو في قاعدة البيانات:
- `has_active_course_access(student, course)` — الدالة المرجعية: كورس مجاني بلا كورسات فرعية، أو اشتراك مدفوع ساري على الكورس أو الكورس الأب.
- `quiz_is_free_lesson_homework(quiz_id)` — أُضيفت 2026-09-01 (migration `20260901090123`): الواجب منشور + درسه منشور ومجاني + الكورس منشور.
- سياسة RLS `quizzes_select` — تضيف حالة الواجب المجاني.
- الدوال: `get_available_quizzes_for_student` (التطبيق)، `get_quiz_questions_for_student`، `submit_quiz_attempt` — كلها `has_active_course_access(...) or quiz_is_free_lesson_homework(...)`.
- `get_quiz_review` — لا يعتمد على الاشتراك أصلًا، بل على ملكية الطالب للنتيجة.
- `api/bunny-token.ts` — يوقّع فيديو الدرس (بشرط الاشتراك أو `is_free_preview`) وفيديو شرح إجابة في اختبارات نفس الكورس (بشرط الاشتراك أو أن درس الواجب مجاني).
- `lesson_files` — سياسة `lesson_files_select`. **✅ صُحّحت 2026-09-02** (migration `20260902162026_align_lesson_files_access_with_course_access`): صارت تستخدم `public.has_active_course_access((select auth.uid()), l.course_id)`، فبقت تحترم انتهاء الاشتراك **وتحترم اشتراك الكورس الأب**. قبل الإصلاح كان المشترك عبر الكورس الأب يرى **صفر ملفات** على الدروس المدفوعة، والمنتهي اشتراكه يظل يراها.
- `lessons_enrolled_read` — **✅ أُضيف `quiz_manager`** 2026-09-02 (migration `20260902195550_allow_quiz_manager_to_read_lessons`)، لأنه كان لا يرى الدروس المدفوعة فلا يستطيع ربط اختبار بها.

## اختبار التحقق بعد أي تعديل على القفل
داخل معاملة، بانتحال هوية الطالب:
```sql
begin;
set local role authenticated;
set local request.jwt.claims = '{"sub":"<student_uuid>","role":"authenticated"}';
select * from public.get_available_quizzes_for_student();
select count(*) from public.get_quiz_questions_for_student('<quiz_uuid>');
rollback;
```
النتيجة المتوقعة: طالب بلا اشتراك يرى 3 واجبات (دروس مجانية) و3 دروس ويُرفض على بنك الأسئلة؛ المشترك يرى 4 واجبات و5 دروس ويصل للبنك.
