# حجب كتاب التأسيس في Cloudinary — 2026-10-07

## البديل المعتمد بطلب كريم — Supabase Storage خاص
- كريم لا يتذكر بيانات Cloudinary وطلب بديلًا. أُنشئ bucket **خاص** باسم `lesson-files`، بحجم أقصى 50MB لكل ملف، وأضيف `lesson_files.storage_path`.
- migration المطبقة: `20261007151847_private_lesson_file_storage.sql`؛ اسم النسخة وتوقيتها مأخوذان من سجل Supabase الفعلي لأن CLI غير متاح محليًا.
- الرفع والحذف للأدمن والمعلم ومشرف المحتوى النشط فقط. القراءة للتحقق من صلاحية الدرس والاشتراك، مع إتاحة ملفات المعاينة المجانية. لا يُنشر رابط ملف عام.
- مخزن عام رُفض آليًا بسبب خطر تجاوز صلاحيات المحتوى المدفوع؛ أُكمل العمل بمخزن خاص وروابط تنزيل مؤقتة دون محاولة تجاوز الرفض.
- رفع ملفات الدروس في `AdminLessons.tsx` انتقل إلى Supabase. صور الأبواب والدروس والكورسات بقيت على نظامها الحالي.
- الرابط الدائم المحفوظ: `/lesson-files/<file-id>`، وصفحة `LessonFileDownload.tsx` تتحقق من RLS وتولد رابط تنزيل لمدة 60 ثانية عند الفتح. لا تُحفظ الروابط المؤقتة في قاعدة البيانات.
- الرابط يعمل مع طريقة فتح الملفات الحالية في تطبيق Flutter دون تغيير كوده؛ إذا لم يكن متصفح الموبايل مسجلًا، يحتاج الطالب تسجيل الدخول في المتصفح للملفات المدفوعة. المعاينات المجانية لا تتطلب دخولًا.
- فحص التنزيل قبل قبول الرفع ثم قبل الحفظ يمنع حفظ ملف محجوب؛ أخطاء الاتصال أو 401 تُظهر رسالة عربية وتسمح بإعادة المحاولة.
- **الكتاب الأصلي لم يُنقل بعد:** لم توجد نسخة محلية في المجلدات التي راجعتها، وCloudinary يرفض تنزيل الأصل. طلب كريم معرفة كيفية حل العطل إذا وفر النسخة: رفعها ثم استبدال رابط السجل الحالي لنفس الكتاب والدرس، مع اختبار التنزيل والصلاحيات. لا يُعلن حل تنزيل الكتاب قبل وصول النسخة ونقلها والتحقق منها.
- تحقق محلي: TypeScript وبناء Vite نجحا؛ خمسة سيناريوهات Playwright ببيانات وهمية نجحت (رفع خاص + فحص مرتين، منع حفظ 401، منع تنزيل غير المصرح، إعادة غير المسجل لتسجيل الدخول مع حفظ الوجهة، تنزيل المصرح). Browser plugin غير متاح؛ استخدم Playwright مستقلًا، وجلسة Chrome الحالية للوصول الإداري دون قراءة بيانات اعتماد.
- مراجعة Supabase الأمنية لم تعرض تنبيهًا متعلقًا بالتخزين الجديد. يُستكمل اختبار رفع حقيقي بعد نشر الواجهة.

## التشخيص الأصلي

- أثناء تشخيص شكوى عدم عمل الحساب، ظهرت صفحة متصفح `HTTP ERROR 401` على `res.cloudinary.com`؛ لا تُعتبر هذه الصورة دليلًا على فشل تسجيل الدخول للمنصة.
- الملف: **تحميل كتاب التاسيس** في درس **الأعداد العشرية**، `lesson_files.id = 4144a0d4-ce03-4081-bdd6-f82102572afe`.
- الرابط: `https://res.cloudinary.com/dzgfvs0gi/image/upload/v1787752443/xkeuagnp53qvq6pf9ycl.pdf`.
- تحقق مباشر بـHEAD مع Referer الموقع: HTTP **401**، و`X-Cld-Error: deny or ACL failure`.
- حساب الطالب محل الفحص نشط وبريده مؤكد وله اشتراك ساري، ودالة `has_active_course_access` سمحت بكورس الملف؛ لا تُحفظ هويته أو بريده في Git.
- صفحة الموقع الرئيسية و`/auth` و`/dashboard` أعادت HTTP 200 أثناء الفحص، وهذا فحص استجابة HTTP فقط وليس اختبار واجهة تفاعليًا.
- المؤكد: Cloudinary يرفض تسليم الملف. **الإعداد المحدد المسبب للحجب لم يُتحقق منه**؛ منع تسليم PDF/ZIP في إعدادات الحساب أو قيود الوصول احتمالات تحتاج مراجعة.
- المرجع الرسمي: https://cloudinary.com/documentation/ts_what_are_the_common_error_codes_returned_in_the_x_cld_error_header_when_delivering_assets
- وقت التشخيص الأول لم تتغير إعدادات Cloudinary أو قاعدة البيانات أو كود المنتج. التعديلات اللاحقة المعتمدة موثقة أعلاه.
